- **A run truncated by a stop condition lost every `Result` field the rebuild
  did not name (issue #559).** `Simulator._truncate_result` rebuilt the partial
  result from eight fields and dropped the rest: all six sensitivity blocks and
  their parameter lists, `_seed` and `_ic_sensitivity_seed`, the #616 reaction
  statistics, the SSA and PSA diagnostics, and the metadata the `Simulator`
  stamps on afterwards. Two of those were worse than a missing value. The
  truncated result is built with `core=None`, where `Result.__init__` fills the
  SSA diagnostics with inert defaults — so a run on the `cc` propensity backend
  came back reporting `propensity_backend == "interpreted"`. And a sensitivity
  run that stopped early raised out of the empty block, telling the caller to
  enable the thing they had enabled.

  Everything is forwarded now: per-time blocks sliced at the stop index, scalars
  and metadata carried whole, and a block whose leading axis is not the time
  axis carried rather than cut in the wrong place. From @Montana.
