- **The output-sensitivity support map is kept with the cached artifact** (#1004). A sensitivity run attaches `{function: why its output sensitivity is not available}` to its result, and the map was worked out again in every process by an analysis that runs under a wall-clock budget. Where the build that wrote the artifact was cut by the budget and a later process's analysis was not, the later process called a function supported that the artifact holds NaN for, and `output_sensitivities([...])` returned NaN with no reason. The map is now written beside the artifact when it is built (`rhs_<key>_<hash>.outputs.json`) and read back on a cache hit, so the later process raises the build's reason, and a warm process no longer pays for the analysis (3 s for a model of 301 functions, 21 s for one of 501). An artifact with no note is analysed as before. `bngsim-cache info` counts both kinds of note under `note` (it said `decline note`).
