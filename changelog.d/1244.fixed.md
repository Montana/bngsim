- A rate law's condition that reads a species only events write, such as a daily pulse whose width `w` an event sets, now gets its stops (issue #1244). Before, it got no stop at all, and X(240) was 1 for 17 at every tolerance, plain or with sensitivities. Where the events that write the species fire at fixed times (`time >= c`, after a constant delay) and set values known before the run, the condition is stopped at stretch by stretch between them, with the species as its value there. A run that continues the last one reads its events as the engine does: a trigger true where the last run ended does not fire again, and an execution delayed into the run sets the value it froze. Where they do not, a condition that changes more than once over the run is refused by name; one that changes once, which its root sees, runs as before. Under SSA the runs were right before and are unchanged.
