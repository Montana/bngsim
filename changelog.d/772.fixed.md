- **`Model.add_table_function` refuses a name the model already has (issue
  #772).** Under a `.net` tfun's name the second table was appended but never
  bound, so the dynamics used the old data while codegen reported the new; under
  a plain function's name the interpreter kept the function's body and compiled
  code read the table, so the answer changed with `codegen`. Both now raise
  `ModelError` and leave the model unchanged, as does a name the expression
  evaluator cannot register, which it used to drop silently.
