- **A forward-sensitivity run no longer returns rows of zeros where CVODES returned an output time outside its last step.** After the sensitivity right-hand side refused a state (the recoverable return of GH #395), CVODES could return the time asked for from a step that did not span it. Its interpolation to that time failed, which CVODES does not report, so the row took the state of the call before, at the time asked for, and its sensitivities were never read and came back as zeros: 24 rows of 101 on MODEL2001200002 (Mpekris 2017), with no error. Each such row is now read where the run stands, as a sensitivity run already records its rows, and counted in `solver_stats["n_rows_outside_last_step"]`; a row whose sensitivities still cannot be read raises instead of reading 0. A run of the same model on `m_T8` that failed with `CV_ILL_INPUT` at t = 91, and finished only on the finite-difference retry, now runs on its own Jacobian. The second SUNDIALS message of each pair, a solver "at t = 2.6e-312", is SUNDIALS 7.2.1's `CVodeGetSensDky1` printing its message without its arguments, not another solver (issue #1301).
